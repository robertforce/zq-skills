# 论文下载与中文翻译规范

## 下载原文

1. 优先使用官方论文页面、会议页面、作者主页或稳定的公开论文库。
2. 将最终 PDF 保存为 `source/paper.pdf`；补充材料保存到 `source/supplement/`。
3. 用户提供本地 PDF 时复制到 `source/paper.pdf`，不要修改原文件内容。
4. 在 `manifest.md` 记录标题、作者、论文 ID、版本、来源 URL、最终下载 URL、下载时间和 SHA-256。
5. 检查文件类型、PDF 页数和可渲染性。响应内容是 HTML、登录页、验证码页、零字节文件或截断 PDF 时视为下载失败。

下载失败时保留失败原因，不创建伪造 PDF，也不进入翻译阶段。

## 翻译目标

生成 `translation/paper.zh-CN.md`，完整覆盖主论文正文。补充材料如果是理解关键实验或结论所必需，也翻译为 `translation/supplement.zh-CN.md`。

翻译稿是忠实中文版本，不是摘要、评论或知乎文章。不得删掉看似不重要的段落，也不得把工程判断混进译文。

## 保留结构

- 保持标题、作者、摘要、章节、小节和段落顺序。
- 保持公式内容与编号，使用 Markdown 支持的 LaTeX 语法；不翻译变量名。
- 保持引用编号、脚注、算法编号、定理和证明关系。
- 保持 Figure、Table、Appendix 等编号，并翻译图注和表注。
- 代码、配置字段、数据集名、模型名和指标缩写保留原文。
- 重要术语首次出现时使用“中文（English）”，后续保持同一译法。

无法可靠翻译或原文不可辨认时使用明确标记，例如 `<!-- 待核实：原文第 7 页此处不可辨认 -->`，不要猜测。

## 图片与表格

按 [images.md](images.md) 从原论文提取图片到 `source/assets/`。译稿在原图对应位置使用相对路径，例如：

```md
![图 3：不同融合方式的在线指标对比](../source/assets/fig-03-main-result.png)

*图 3：不同融合方式的在线指标对比。原文 Figure 3，第 7 页。*
```

简单表格优先转为 Markdown 并翻译表头，所有数值保持不变。复杂表格可以保留原图，同时翻译表注并补充可访问的文字说明。不得仅保留“Image”占位符。

## 分段翻译

论文超出单次上下文时：

1. 先建立章节清单和术语表。
2. 按章节顺序翻译到临时分段文件。
3. 合并为单一 `paper.zh-CN.md`。
4. 统一术语、标题层级、引用和图片路径。
5. 完成检查后删除或归档临时分段，避免把半成品误认为完整译稿。

分段翻译不能改变最终交付要求：目标文章只能在完整译稿生成后开始。

## 完整性检查

将原始 PDF 与译稿逐节对照，至少确认：

- 主论文所有章节和附录入口均存在。
- 段落没有因分页、双栏解析或脚注而丢失或乱序。
- 所有公式、图、表和引用编号均能在译稿中找到。
- 图片路径存在，图注和表注已经翻译。
- 数值、单位、模型名、数据集名和指标方向没有被改写。
- 译者补充内容均明确标记为“译注”，没有混入论文正文。

检查通过后，在 `manifest.md` 将翻译状态设为 `translation_complete`。存在缺失时使用 `translation_incomplete`，并阻止精读成稿流程继续。
