# 知乎交付与发布链接归档

## 进入条件

同时满足以下条件才准备知乎编辑器：

- `article/article.md` 存在且 `review_status: approved`。
- `article/draft.md` 不存在。
- `manifest.md` 与 `article/review.md` 已记录用户人工批准。
- 正文图片、公式、表格和外链通过最终检查。

自动质检不能替代人工批准。可以使用浏览器已有登录会话，但不得自动登录、填写密码、处理验证码或点击最终“发布”按钮。

## 填入编辑器

1. 读取批准稿，去掉 YAML frontmatter 和一级标题；一级标题单独填入知乎标题框。
2. 优先使用知乎支持的 Markdown 导入或粘贴，使标题层级、列表、公式、表格和链接转为富文本。
3. 文章本地图片仍以 `article/assets/` 为事实来源。优先通过页面文件选择器上传本地文件；若编辑器只能从 Markdown 拉取图片，可以临时替换为论文官方、稳定、可公开访问的图片 URL，但不得改写本地批准稿。
4. 远程图片必须来自论文官方页面、作者主页或会议页面。图片进入知乎后核对数量、顺序和图注，不能把上传失败占位符留在草稿中。
5. 等待编辑器显示草稿已保存，再进入发布前检查。

## 清理图片空段

Markdown 导入知乎后，图片原子块两侧可能各产生一个空的普通段落。对每张图片执行：

1. 记录编辑器中的图片总数。
2. 选中图片原子块，按 `ArrowDown`；确认当前选择恰好落在图片后的空段，再按 `Delete`，使后续图注并入该段。
3. 重新选中同一图片，按 `ArrowUp`；确认当前选择恰好落在图片前的空段，再按 `Backspace`。
4. 每次删除后确认图片总数未变化；若图片被删除，立即撤销并重新定位。

不要仅凭按键执行成功判断结果。最终逐张确认前一块和后一块都有非空文字，后一块必须是对应图注。

## 发布前门禁

至少检查：

- 标题与批准稿一致。
- 正文图片数量与批准稿一致，无“上传失败”“图片上传中”或“重试”。
- 每张图片前后无空段，图注紧随对应图片。
- 公式、表格、列表和原论文链接存在。
- 页面显示“草稿”且“预览”“发布”按钮可用。

通过后在 `manifest.md` 记录 `publication_pending_human`，保留编辑页供用户人工预览和点击发布。不得自动点击。

## 记录公开链接

人工发布后：

1. 从公开文章页、浏览器当前页或用户提供内容中取得 URL。
2. 去掉查询参数和锚点，只接受 `https://zhuanlan.zhihu.com/p/<数字>`。
3. 拒绝 `/write`、`/edit`、预览链接和无法确认对应当前文章的页面。
4. 将以下字段写入 `manifest.md` 和 `article/review.md`：
   - `publication_status: published_manually`
   - `publication_url`
   - `publication_record_source: browser_public_page | user_confirmation`
   - `publication_recorded_at_utc`
5. 重跑时若规范 URL 相同，只更新时间或补充缺失字段；若 URL 冲突，停止并请用户决定，不静默覆盖。
